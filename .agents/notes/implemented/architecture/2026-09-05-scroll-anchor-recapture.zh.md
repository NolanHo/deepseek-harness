# Agent Note：普通滚动、前插与重挂载后重新捕获分页锚点

Status: implemented

[English](2026-09-05-scroll-anchor-recapture.md) | 中文

> 范围：`ui-chat` ChatView 锚点生命周期。以 `ChatView.tsx` 四处 fork 编辑扩展重排稳定滚动锚点（[note](2026-09-05-reflow-stable-scroll-anchor.zh.md)）。

## 问题

重排补偿器只在持有分页锚点时校正高度变化，但锚点仅在跳转与前插路径上创建、在 load-earlier 结算时被清空，而普通读者滚动只刷新既有持有。生产浏览器实测：一次 Load-earlier 前插之后，展开阅读行上方一个折叠的 127 工具调用块（+8,460 px 流高度）把读者的行整体推移了完整差值，`scrollTop` 补偿为零。凡读者仅仅滚离钉住尾部的会话都没有锚点，于是阅读行上方的折叠、图片加载与展开在会话持续加载时不断跳动页面。

## 决策

ChatView 在读者可到达的每条路径上都武装锚点，让补偿器始终有行可用：离开底部的滚动采样捕获它（`else if (position !== null)`）；前插补偿臂在跳转未取得所有权时于补偿后位置重新持有读者行（已落地跳转的目标行仍是锚点）；保存位置恢复臂捕获恢复的行；并移除上游在 `loadingOlder` 离开忙态时清空锚点的 effect——锚点现在也拥有非前插重排，结算后仍然需要它。失败或空页不会移除头部行，而过期的 top 由下一次补偿刷新。

`restoreAnchorOnReflow` 现在在滚动写入之后测量重捕获锚点：滚动耦合几何下补偿完成后行回到其锚定流偏移，记录写入前的值会让同一次重排的第二个回调算出负差值并撤销补偿。

选择在 ResizeObserver 臂内重新捕获之外的方案：观察器没有推导读者位置所需的滚动几何，而滚动采样已经算好了一份。选择保留结算清空、仅在下次滚动时重新武装之外的方案：结算与读者下次滚动之间落地的折叠正是实测到的跳动。

## Alternatives considered

- **在 ResizeObserver 臂内重新捕获**：观察器缺少该位置所需的滚动几何；在那里复制会分叉 `scrollPosition`。
- **保留结算清空、下次滚动时重新武装**：结算与读者下次滚动之间落地的折叠保持不补偿——即生产实测。
- **上报上游**：该守卫与清空是上游有意为之（那里的锚点只拥有前插）；在没有 fork 补偿器的情况下上报并不能修复 fork 的页面。

## 验证

`chat-view.client.spec.tsx` 四个红先组件测试（普通滚动捕获、前插重新持有、恢复捕获、结算保留——每个都在未修复源码上因折叠差值未补偿而失败），修复后 87/87 全绿；完整 GUI lane 通过（3,944），chat-view 套件在 coverage lane 配置下（forks pool + v8，连续三跑）87/87 通过——单套件调用非零退出仅源于未触碰文件的仓库级逐文件阈值。锚点单测使用滚动耦合几何并钉住连续回调幂等（两个文件共 95 个测试）。生产浏览器插桩：拦截 `scrollTop` 写入与逐帧采样显示修复前 8,460 px 推移与零补偿；修复后同样的展开位于补偿臂的覆盖之下。

## 后果

- 普通滚动、load-earlier 前插与页面重挂载之后，阅读行上方的折叠、图片加载与展开都保持补偿——读者在会话持续加载时看到的跳动消失。
- 锚点持有得更久，补偿器在更多列尺寸变化上执行矩形读取；差值为零时不写入，开销由尺寸变化节奏而非渲染节奏约束。
