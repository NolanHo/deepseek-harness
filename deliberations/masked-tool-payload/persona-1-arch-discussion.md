# persona-1-arch-discussion.md

## 对 P2（产品体验师）

**认同**：其用户感知论证成立——首屏 6.35MB 中可见文本仅约 2.3%，为不可见工具日志付冷启动代价确属浪费；「摘要可扫读、展开延迟补偿、移动端分批」三条是必要非功能需求，我采纳为验收约束。

**反驳**：P2 把 UX 目标默认可由「mask 摘要 + 带外专门 API」满足，未论证该协议路径的必要性。其三点完全可被**无损、可寻址、对称可展开**的按需拉取满足，且不引入第二事实链；协议层不应因交互诉求就放弃 wire 权威性。结论：不改变我的协议判断。

## 对 P3（一致性守门员）

**高度认同**：其「mask 只改 wire 表示、不得改事实来源」「展开内容必须从权威 session log 投影、不得另建旁路缓存」与我的单一事实源完全一致；「降级路径为硬前提」我也采纳。

**补充/反驳其不足**：P3 未点明「按需拉取必须复用现有 seq/cursor 事件寻址与 chunk-row 对称解码」，否则仍会退化为带外端点、分裂客户端路径。我坚持：新读取面必须是现有事件寻址之上的**范围投影**，而非新端点 + 摘要枚举。

## 是否修正立场

**核心立场不变**（有条件支持；反对 mask 摘要 + 专门 API）。**补强约束**：在既有事件寻址之上做无损、对称、可展开的按需投影，附确定性计数、失败降级路径，并满足 P2 的展开延迟补偿与分批要求。

LEAD-SUMMARY: 认同 P2 用户体验诉求、与 P3 单一事实源高度一致；立场不变并补强：按需须复用事件寻址做无损投影，附降级路径。
