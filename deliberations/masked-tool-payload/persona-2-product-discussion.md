# persona-2 讨论稿

## 对 persona-1（架构）
- 认同「单一事实源」是底线，但产品视角补充：用户不关心 wire 上是「mask」还是「投影」，只关心首屏快、展开准、内容可信。因此不要把摘要做成带外第二事实链，而应是对权威 transcript 的无损投影视图——这是我们立场的交集。
- 对其「拒绝 mask 摘要」部分反对：mask 作为 wire 表示可以存在，只要展开内容能从同一权威源无损还原，产品层就成立。
- 认同「先修 sourceEventSeqs 与 reasoning/tool-call 多重表示」：这是更便宜的第一刀，且同样改善首屏体感，应优先做。

## 对 persona-3（一致性）
- 完全认同「mask 只能改 wire 表示，不能改事实来源」与「必须保留降级路径」。
- 产品层补充：降级体验要体面——按需 API 失败时应渐进回退为完整读取并给进度反馈，而非白屏或整页重算。
- 其「确定性、可校验、展开无损的计数」正是我「摘要可读」前提的工程化表述，双方一致。

## 立场修正
仍为有条件支持，但收紧条件：折叠必须以权威 session log 为单一来源、可无损展开、有明确降级路径；「专门 API」仅作为投影读取面，不得另建第二缓存。产品方向不变，工程底线向 1/3 号对齐。
