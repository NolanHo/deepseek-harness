# persona-3 一致性守门员 · 初始立场

**立场：有条件支持**（以保留数据完整性与降级路径为硬前提）。

## 关键理由 / 最大风险

1. **model-visible ⟺ logged 不变量**：mask 只能改 wire 表示，不能改事实来源。展开所请求的完整 tool I/O 必须从权威 session log 投影/解码，不得另建旁路缓存；否则会出现「模型可见但日志不可见」或「日志可见但首屏不可见」的分叉，破坏可重构性。

2. **搜索索引与投影缓存不变量**：tool 输入/输出在当前单页解压 payload 中占约 27%（tool/call.arguments + tool/code-dispatch + tool/result）。若 wire 只留摘要，必须证明全文搜索索引与 projection cache 仍消费同一来源并可无损重建，否则搜索命中与缓存内容会静默丢损。

3. **折叠正确性 + 前提未证**：摘要计数（26 次 / 20 条 / 13分25秒）必须是确定性、可校验、展开无损的；而当前代码无 mask、无按需 API、无折叠统计逻辑（research.md D 节），前提不成立。新增读取面必须先给失败降级路径（按需 API 不可用时如何退化为完整读取）再上线。
