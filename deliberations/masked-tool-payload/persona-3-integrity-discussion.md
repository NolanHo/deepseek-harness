# persona-3 一致性守门员 · 讨论

## 对 persona-1（架构）
- 认同「单一事实源」与「mask 不可逆 = 两条事实链」：这正是 model-visible ⟺ logged 在协议层的体现。
- 认同「前提被证伪、只 mask tool/result 会漏 tool/code-dispatch.content 大头」：属折叠正确性必须防的静默丢损。
- 「带外专门 API」部分认同：它确会分裂读取面，但若作为同一 session log 的按需投影（复用 seq/cursor 寻址）则风险可控，不必一刀切禁止。

## 对 persona-2（产品）
- 认同摘要可读、展开顺滑、移动端分批；但这些是体验约束，不得凌驾完整性：摘要计数必须由权威事件确定性派生，展开必须无损可校验，否则「可读」会变「误读」。
- 「分批加载」应只是读窗口，不能变成事实分片缓存，须与单一事实源一致。

## 是否修正立场
是。由「有条件支持 mask 摘要 + 专门 API」收紧为：支持按需减负方向，**反对不可逆 mask 成摘要 + 带外专门 API**；与 persona-1 合流为「既有事件寻址之上的无损、可寻址、对称可展开按需投影」，并保留我的硬约束：搜索索引/投影缓存同源重建、计数确定性、失败降级路径。

LEAD-SUMMARY: 守门员与架构派合流：反对不可逆 mask 摘要+带外专门 API，改无损可寻址按需投影，并须搜索/缓存同源、计数可校验、有降级路径。
